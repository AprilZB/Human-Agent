# 甲丁智能体（一期）- 部署方案

由于IT团队目前由单人负责运维，本项目的部署策略核心为：**环境极简、内网隔离、复用基础。** 

## 1. 部署环境规划
不单独设置独立的测试环境服务器，采用 `开发环境` -> `生产环境` 两层架构。
所有系统与服务均部署在企业内网，不可暴露在公网，满足医疗数据合规性要求。

### 1.1 硬件/虚机资源配置建议 (生产环境)
- **前端 Web 服务器**：2C 4G (Nginx)
- **后端 API 服务与规则引擎**：4C 8G (Python 3.10+)
- **业务数据库**：复用现有的 APHR MySQL 8.x 实例集群（建独立 Database），或新开 4C 8G 实例。
- **大模型推理节点**：**复用现网资产** ThinkPad PGX，无需额外采购 GPU 服务器。

## 2. 各层级部署说明

### 2.1 大模型层 (vLLM on ThinkPad PGX)
- 已经通过本地 Docker 部署 `Qwen2.5-14B-AWQ` 与 `Gemma-31B-AWQ`。
- **运维动作**：确保暴露的 API 接口在内网对后端 API 服务器所在 IP 段放行。如遇高并发排产计算，可通过限制 `max-model-len` 等参数防止显存溢出（OOM）。

### 2.2 工作流引擎层 (Dify)
- 建议采用 Dify 官方推荐的 `docker-compose` 方式进行一键部署。
- 将已部署的 vLLM 作为本地模型提供商（Model Provider）接入 Dify。
- 将企业微信/钉钉等内部通道配置好，并生成 API Key 提供给后端 FastAPI 服务调用。

### 2.3 后端业务层 (FastAPI)
- **部署方式**：**Docker 容器化部署**（生产环境强制要求）。
- **Dockerfile 建议**：基于 `python:3.10-slim` 构建，安装 `requirements.txt`。
- **运行命令**：使用 `uvicorn` 或 `gunicorn` + `uvicorn workers` 启动。
- **环境变量**：所有数据库密码、内网 API 密钥（APHR / 钉钉 / vLLM）通过 `.env` 或 Docker 环境参数传入，严禁硬编码。
- **端口分配**：后端端口将从系统的全局端口记录表中读取（如 `8100`），避免与同机器的其他系统容器发生冲突。

### 2.4 前端展示层 (Vue 3)
- **构建**：执行 `npm run build` 打包静态资源。
- **部署方式**：基于 **Docker** 中的 Nginx 容器承载。
- **配置要点**：
  - 配置 `try_files $uri $uri/ /index.html;` 支持 Vue Router 的 history 模式。
  - 配置反向代理，将 `/api/` 路径的请求代理至后端的 Docker 容器端口。
  - **端口分配**：前端暴露端口需从全局端口记录表中获取（如 `8101`），保持前后端端口的就近连贯性。

## 3. 数据安全与备份策略
1. **数据隔离**：业务表与日志记录表分离，防止日志撑爆业务库。
2. **定时备份**：配置 MySQL Dump 脚本，每日凌晨对甲丁业务主数据执行全量备份。因为核心人员和考勤等数据依然在 APHR，甲丁的数据丢失带来的灾难性较小，但排产及加班审核流水必须保证可追溯。
3. **网络安全**：API 服务不对外暴露，只有内网和特定 IP 能够访问，保护由于免密接口或过渡期 SSO 未完成带来的安全风险。
