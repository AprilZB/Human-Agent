# 甲丁智能体（一期）- 系统功能与配置项

## 1. 角色与权限矩阵 (RBAC)

系统在一期核心预设以下三个角色。通过复用 APHR 的组织与账号体系进行身份认证，在甲丁侧完成角色与权限的关联分配。

| 功能模块 | 车间主管 | 班组长 | 系统管理员 |
| :--- | :---: | :---: | :---: |
| **大屏登录/首页看板** | ✅ (车间全视角) | ✅ (班组内视角) | ✅ (全局视角) |
| **排班考勤看板查看** | ✅ | ✅ | ✅ |
| **智能人岗匹配结果调整** | ✅ (可调整及最终确认) | ✅ (可微调/建议) | ❌ |
| **一线员工日评分录入** | ❌ (交由班组长管理) | ✅ (仅限本班组成员) | ❌ |
| **加班申请发起** | ✅ (代班组长/员工发起) | ✅ (代员工发起) | ❌ |
| **加班审批流节点** | ✅ (作为终审/二审节点) | ✅ (作为初审节点) | ❌ |
| **生产数据录入** | ✅ | ✅ | ❌ |
| **管理后台：主数据录入** | ✅ (订单录入) | ❌ | ✅ (全量主数据维护) |
| **管理后台：系统配置项** | ❌ | ❌ | ✅ |

> **注**：登录时会判断用户的“生产人员”和“普通员工/管理岗”属性：
> - 生产人员默认进入极简大字版大屏确认视图（签到、通知、评分）。
> - 普通员工/管理岗可访问后台配置。

## 2. 系统核心功能详细说明

### 2.1 订单—人岗智能匹配推荐（核心功能）
- **功能描述**：根据手工录入的生产工序需求（工种、所需人数、工序技能要求、交期），系统自动给出最佳生产人员指派建议。排产颗粒度精细到“工序”级别，而非粗放的“订单”级别。
- **业务规则**：
  - **前置过滤**：排除今日请假人员、已排满人员。
  - **技能匹配**：必须具备目标工序的技能标签（员工技能档案根据工序记录）。
  - **合规约束求解**：排除连续上班天数超限者、近期加班时长逼近红线者。
- **大模型职责**：接收规则引擎初筛出的候选人列表和打分原因，生成自然语言推荐话术（如：“推荐张三：拥有切割A级技能，近7日未加班，且当前处于空班状态”）。

### 2.2 排班/请假/考勤信息看板
- **功能描述**：大屏端可视化展示当天的车间与班组出勤状态。
- **数据流转**：通过 API 从 APHR 拉取数据并在前端聚合展示（甲丁不存考勤过程数据）。
- **展示维度**：班组出勤率、缺勤人员明细、近期异常考勤预警。

### 2.3 加班申请审批流程
- **功能描述**：从报表查看、申请提交到审批流转的全闭环管理。
- **业务流程**：班组长在大屏端发起加班申请 -> 合规校验（防疲劳预警） -> 主管大屏端或钉钉端一键审批 -> 审批结束。
- **数据闭环**：后期审批通过后自动通过外部接口写入第三方加班系统及 APHR。

### 2.4 一线员工日评分
- **功能描述**：班组长对班组成员的每日主观打分。
- **功能特性**：极简交互，大屏卡片式快速打分，特殊评分要求必填备注。
- **数据闭环**：保存后调用 APHR 绩效 API 进行归档。

### 2.5 生产数据记录
- **功能描述**：记录车间每日/每班次产量与质量数据。
- **填写字段**：批次号/工单号、合格率、不良品数量、不良类型勾选。
- **演进策略**：一期管理后台手工填报，二期接入 SAP 定时同步，保留手工修改作为补录通道。

## 3. 核心配置参数项（管理员维护）

系统在数据库中应配置一张 `sys_config` 表，供管理员在管理后台调整业务规则，而无需改动代码：

| 配置键 (Key) | 配置说明 | 默认值 (一期占位) |
| :--- | :--- | :--- |
| `OVERTIME_MAX_HOURS_PER_MONTH` | 员工单月最高允许加班时长上限（小时），超出则拦截或标红警告 | `36` |
| `MAX_CONSECUTIVE_WORK_DAYS` | 最大连续出勤天数（防疲劳合规，触发则不可推荐排班） | `6` |
| `API_APHR_BASE_URL` | APHR 系统的 API 根路径 | `http://aphr.internal/api/v1` |
| `API_DINGTALK_SERVICE` | 内部钉钉消息推送服务的地址 | `http://dingtalk.internal/send` |
| `LLM_BASE_URL` | 内部 Docker vLLM 提供的大语言模型 API 接口地址 | `http://localhost:8000/v1` |
| `LLM_MODEL_NAME_MAIN` | 主要执行匹配文案生成的大模型名称 | `qwen2.5-14b-awq` |
| `DIFY_API_KEY` | Dify 工作流调用鉴权 Key | `sk-xxxxxx` |
| `ENABLE_AUTO_PUSH_TO_APHR` | 是否开启将数据自动回写到 APHR（开启前供测试环境兜底用） | `false` |

## 4. UI与视觉规范

- **主题风格**：系统需提供明亮（极简科技风）与暗黑（深邃暗黑风）两套主题色系，整体色系参考 `http://localhost:8099/` 的视觉规范。
- **Logo与图标资源**：统一使用存储在 `d:/dev/logo` 目录下的系统Logo与图标资产。
