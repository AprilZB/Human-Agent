# 甲丁智能体（一期）- 技术架构设计

## 1. 总体架构总览

甲丁智能体采用典型的五层架构设计，确保核心业务（强规则）与AI大模型（自然语言处理）解耦，保证医疗器械制造场景的强合规性和可解释性。

### 1.1 分层说明

1. **展示与推送层**
   - **数字化大屏 / 车间操作界面**：面向车间主管和班组长，提供科技感UI及大字号易操作面板。按“生产人员”和“普通员工”自动路由不同视图。
   - **独立管理后台**：用于订单、排班、加班等主数据的维护和手工录入。
   - **推送服务**：通过接入 dingtalk-service 实现钉钉消息与通知的触达。

2. **业务服务层 (FastAPI)**
   - 核心业务逻辑承载区，提供：订单解析服务、合规审批流（加班）、人员评价服务、生产录入服务等。
   - 实现权限控制、用户路由分发以及系统参数动态读取。

3. **智能体编排层 (Dify & 自研规则引擎)**
   - **规则引擎（核心）**：用代码实现的约束求解器，处理技能匹配、排班冲突、加班时长合规等强规则判定，不容忍幻觉。
   - **Dify 工作流**：处理开放式自然语言交互、统计查询问答、以及催办/提醒逻辑的轻量编排。

4. **模型服务层 (vLLM)**
   - 复用本地部署的 ThinkPad PGX 算力集群，通过 Docker vLLM 提供推理 API。
   - 双模型驱动：`Qwen2.5-14B-AWQ`（主导业务文本解释与匹配理由生成）与 `Gemma-31B-AWQ`（备选或高阶复杂推理）。

5. **数据接入与存储层**
   - **本地存储**：MySQL 8.x (部署于 `10.11.100.202`，账号 `root` / `Mtdb@123`)，用于存储甲丁自有业务数据（系统配置、局部审批流状态、临时表等）。
   - **数据集成桥接器**：以只读/回写方式通过 API 与企业核心 IT 资产（APHR、SAP）打通。

---

## 2. 核心技术栈

- **前端**：Vue 3 + ECharts/DataV（大屏可视化） + Element Plus（后台管理）
- **后端**：Python 3.10+，FastAPI 框架，SQLAlchemy 2.0 (ORM)
- **数据库**：MySQL 8.x
- **大语言模型与编排**：vLLM（推理加速框架），Dify（轻量工作流搭建）
- **部署方式**：Docker 容器化部署，前后端分离，Nginx 反向代理

---

## 3. 数据库与数据架构设计

遵循“复用现有IT资产优先”及“避免数据双重来源”原则。

### 3.1 本地主库设计 (MySQL)
甲丁智能体自有的 MySQL 数据库仅承载以下核心实体：
- **订单/排产表**：生产任务、需求技能、需求数量、交付时间。
- **加班审批状态表**：内部审批流转记录（审批人、节点、意见、状态）。
- **生产记录表**：合格率、不良品类型、数量（人工填报，后备SAP同步表）。
- **系统配置与权限表**：角色权限矩阵、全局合规阈值设定（如：连续上班天数上限）。
- **打分记录流水表**：缓存班组长提交的评分和备注（待写入 APHR 成功后可标记已同步）。

### 3.2 外部数据源依赖策略
- **APHR (人事系统)**：
  - **只读**：员工基础信息、技能标签、组织架构、当日/近期排班、请假状态、考勤明细。
  - **回写**：日评分（对接绩效体系）、最终加班记录（归档人事档案）。（注：具体回写字段内容与 APHR 所需配合的操作，将在本期开发完成后整理输出规范）。
- **第三方加班审批系统**：
  - 一期：人工导出/代提交方式过渡。
  - 后期：系统API对接。
- **SAP**：
  - 后续用于读取排产计划和底层生产数据字段。

---

## 4. 架构设计原则总结
1. **规则+模型辅助，人工最终确认**：排产决策的规则可能会相对宽泛，由大模型基于宽泛规则生成匹配推荐与自然语言依据后，最终交由用户（主管/班组长）检查并确认，不完全依赖规则引擎的绝对限制。
2. **前后台分离与按权路由**：管理后台与操作大屏入口分离，基于角色和人员性质（生产岗/非生产岗）自适应渲染界面。
3. **接口防腐层设计**：通过统一的外部系统接入层调用 APHR / SAP，为一期（手工）与二期（API直连）的平滑切换提供代码级解耦。
